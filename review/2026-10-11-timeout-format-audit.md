# 独立格式与时限审查

日期：2026-10-11 UTC。范围：交接快照中 `GlmBrain`、五个搜索提供方、模型 JSON 解析与 HTTP/研究总时限。未调用真实或付费 API，未使用用户本机，未改动部署。本审查增补了独立回归，以下最终结果基于合并后的候选实现。

## 本次实际复现

1. **整轮研究没有自己的总时限。** 旧 `reply` 串行执行最多三条主查询、两条补查；每个 HTTP 请求重新使用完整超时。合成最多三次候选，每次相关性与事实检查各最多两次，剪枝后还可能再审核。包含规划、证据复审和表达，代码允许最多约 27 次模型调用。以原默认每次 180 秒估算，仅模型部分的理论累计上限可超过 81 分钟，尚未加搜索和正文读取。这是代码路径上限，不是实测线上耗时。
2. **合法 JSON 的 `null` 会跳过可恢复的格式路径。** `parseStructuredResearchAnswer('null')`、`parseResearchNarrative('null')` 和事实审核在 JSON.parse 后的 `try` 外直接取属性，产生原生 TypeError。对合成的动态 mock 复现显示，这会绕过已有的有限格式修复。
3. **从数组或多份对象中摘取第一份，会将无效模型协议误判为有效。** 旧 `extractJsonObject` 接受 `[合法答案]`、`["额外值", 合法答案]` 和两份相邻 JSON 对象；选句协议同样受影响。单个代码围栏对象和字符串内部转义引号/花括号应继续正常解析。
4. **搜索响应的类型断言不是运行时校验。** 五个提供方收到 HTTP 200/null 均曾抛 TypeError；四个会把根数组当成空结果。结果集合不是数组、集合中一个 null 或错误类型项，可拖垮同批正常结果。可选 author、media、publishDate 若是数字或对象，也会在候选准备阶段的 `.slice()` 处抛异常；已用五个提供方的畸形元数据回归覆盖。Exa 的非法/空白 highlight 还可能被算作可用结果；Contents 的一个 null 行可使本可读取的正文全部丢失，空白正文曾被标为已读取。
5. **无视 AbortSignal 的实现不能只依赖信号。** 普通 fetch 本身会遵守信号，但注入的搜索执行器或测试 fetch 若永不完成，旧调用方无法按时取回控制权。总时限及 HTTP 边界需要 race 与取消传播共同约束，同时保留用户取消为取消，不能伪装成完成答案。
6. **旧公开入口遗漏取消信号且 JSON 合同不一致。** `beginToolTurn`、`planWebSearchQuery`、`planImageWebSearchQuery` 原未把 request.signal 交给 complete；后两者仍仅裸 JSON.parse，主研究链可接收的单个 JSON 围栏会在旧入口失败。

## 明确排除的误报

原生 fetch 的请求 AbortSignal 会继续作用于响应正文读取。独立本地 HTTP 服务先发送 headers 和不完整 JSON，再永不结束正文；原实现在 100 毫秒预算下约 113 毫秒中止。**不能因为 `response.text()` 写在 fetch 之后，就声称旧 HTTP 正文读取没有超时。** 新共享读取器的收益是可释放计时器、统一的响应大小和对象类型上限，以及非配合实现的调用方时限。

## 回归与证据

测试文件：`tests/timeout-format.test.mjs`。覆盖非对象 JSON、数组和多对象包装、围栏/转义正例、null 后的限定格式修复、五提供方的坏响应和混合行、正文读取中止、正文空白、响应字节上限、跨查询共享预算、无视 signal 的执行器、用户取消及旧入口的信号传播。

第一组 50 项在修复前快照为 17 通过、33 失败。失败数包含同一缺陷的多个提供方和边界用例，不表示发现了 33 个独立问题。随后补充了 12 项回归。2026-10-11 11:15 UTC 对合并后的候选代码执行 `node --test --test-concurrency=1 tests/timeout-format.test.mjs`，最终 **62 通过、0 失败**，约 0.9 秒；输出保存在 `evidence/fixed-timeout-format.log`。本文件是专题回归，完整套件、补丁应用和类型检查由总体验证另行记录。

这些测试只证明确定性的格式、协议和时限约束，不能证明真实模型遵循 schema、真实搜索召回质量、网页当前可访问，或自然语言事实正确。仍需完整项目集成与获批预算下的真实案例验收。
